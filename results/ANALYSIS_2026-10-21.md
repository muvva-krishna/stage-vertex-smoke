## A. The six functional-only runs (slot_02 × flash-lite)

Run IDs (all in `results/runs/`):
- `which-realistic-debuggin-slot_02-combined-TIER_B-r00` / `-r01`
- `which-realistic-debuggin-slot_02-state_snapshot-TIER_B-r00` / `-r01`
- `which-realistic-debuggin-slot_02-symptom_only-TIER_B-r00` / `-r01`

Stored oracle groups, identical in all six: `dedup_case_variants`,
`distinct_kept`, `repeat_import_stable` PASS; `compat:store_schema` PASS;
`compat:cli_help` FAIL. Totals 70.0.

Observed (diffs + trajectories):
- combined r00/r01: agent rewrote `importer.py` (29→64 lines) and
  `normalize.py`, renaming the argparse positionals so `csv_file` no
  longer appears in `--help` output. Its own trajectory shows
  `test_run import and re-import → FAIL` — it observed the failure and
  finished anyway.
- state_snapshot r00/r01: agent replaced argparse with manual `sys.argv`
  handling (`csv_path`/`store_path`); `--help` is unsupported, so the
  oracle's `--help` check fails. Its own `test_run help output → PASS`
  checked something weaker than the oracle.
- symptom_only r00/r01: same pattern (`import_contacts(csv_path,
  store_path)` via `sys.argv`, no `--help`). Its trajectory shows
  `test_run import_and_dedup → FAIL` followed by
  `verification import_and_dedup → PASS` — a recorded instance of an
  inaccurate final claim contradicting the agent's own test result.

Interpretation (minimal): each repair fixed the dedup behavior while
dropping the existing `--help`/argument interface the oracle pins. No
trajectory evidence explains *why* the model rewrote the CLI rather than
editing `store.add`; that cause is unresolved.

## C. The 10-turn/action protocol — what traces establish

Final attempts of the 53 completed cells: 29 hit the 10-turn cap
(≥10 `model_reply` events), 24 stopped early (finish or error); 37 ran
≥1 test op, 16 ran none; 6 hit the cap with zero test ops; 24 of 71 run
dirs contain an invalid-response or rejected-action error note.

Established: the cap binds in practice (29/53 finals exhausted it); a
large minority of attempts (16/53) never invoke the one operation that
earns verification credit; protocol errors are common (24/71 dirs).
NOT established: that the 10-turn limit caused the zero full-pass rate.
Turn-exhausted attempts include drifting ones (repeated `ls`, rewrites
against imagined APIs), and early-stopping attempts also failed — the
traces cannot separate "needed more turns" from "would never converge."
(Test-op counts coincide across denominators here because retry dirs
almost never contain test ops.)

Also established: 4 completed cells produced EMPTY oracle group sets
(`slot_02 repro_log` TIER_A r00 and TIER_B r00/r01, `slot_02
symptom_only` TIER_A r01) — the agent broke module imports (`from store import Store`,
`normalize_key`→`normalize_email` renames without updating importers),
so the oracle script itself crashed before printing any group. These are
unscored breakage, and they expose an oracle-robustness gap: future
oracles should catch per-group exceptions and report all-FAIL instead of
crashing. Artifacts unchanged; noted here only.
